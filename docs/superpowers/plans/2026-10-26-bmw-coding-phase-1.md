# BMW Coding Phase 1 (Read-Only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks that write SwiftUI views also load `swiftui-specialist` and `swiftui-whats-new-27` (the SDK on this Mac is 27.1).

**Goal:** A SwiftUI app for iPhone and Mac that connects to an OBDLink CX over Bluetooth LE, reads the VIN, lists the modules on the car with their identification and coding files, and saves every module's raw coding data to a JSON backup. It never writes to the car.

**Architecture:** All logic lives in a local Swift package `BMWCodingCore` (`Core/`), tested from the command line with `swift test` against a fake adapter link, so no task needs a simulator or the car until the UI tasks. The app target (`App/`, generated by xcodegen from `project.yml`, one target with iPhone and Mac destinations) is a thin step-by-step flow over the package. Everything runs on the main actor; the one adapter command in flight at a time is enforced by awaiting each command on the single `BLELink` instance.

**Tech Stack:** Swift 6 language mode, Swift 6.4 toolchain, SwiftUI, CoreBluetooth, Swift Testing, xcodegen 2.45, no third-party packages.

**Spec:** `docs/superpowers/specs/2026-10-26-bmw-coding-app-design.md`. Facts about the adapter and cars are in `BRIEF.md`.

## Global Constraints

- Deployment targets iOS 26.0 and macOS 26.0 (same as Scott's other projects; the spec's "current major" is read as the floor his devices certainly meet). SDK is 27.1, so the `@State` macro rules apply: never give a `@State` property an initial value and also assign it in an `init`.
- `SWIFT_VERSION` 6.0 language mode, `SWIFT_STRICT_CONCURRENCY` complete, default actor isolation `MainActor` in both the package (`.defaultIsolation(MainActor.self)`) and the app (`SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor`).
- No third-party packages. No raw command console. Nothing sends anything but adapter setup, UDS `0x22` reads, `0x3E` tester-present and `0x10 0x03` session control.
- Bundle id prefix `com.smidley`, team `5CNQA36678`, automatic signing, hardened runtime, no app sandbox on the Mac (as Dustpan).
- Every AT command and every CAN frame sent or received goes through `Log`, exactly as transmitted.
- Each task ends with `swift test` green (package tasks) or a successful build (app tasks), then a commit. Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Adapter values that the spec marks for verification in the car are pinned here as the first guess; Task 15 is where the car corrects them.

## Review Focus

- Adapter error lines mid-request (`CAN ERROR`, `STOPPED`, `BUS ERROR`, `?`), typically because the ignition is off: the request throws `LinkError.adapterError` with that text, the step shows it, nothing crashes. Test in Task 4.
- A module sends a first frame but no consecutive frames even after the manual flow-control frame: the request resolves to `.noResponse`, the log keeps the frames, discovery moves on. Test in Task 4.
- Backup interrupted mid-module (adapter gone, car switched off): no file is written, remembered sets are untouched, the screen says which module it stopped on. Test in Task 11.
- A VIN read that returns the wrong length or characters outside `A-HJ-NPR-Z0-9`: rejected, next candidate module tried, clear failure if none answers. Test in Task 8.
- A module that answers tester-present but refuses every identification read: listed by bare address, backed up, its backup entry marked `partial`. Tests in Task 7 and Task 11.

### Task 4: Diag: module selection, UDS reads, tester-present, session

**Files:**
- Create: `Core/Sources/BMWCodingCore/Diag.swift`, `Core/Tests/BMWCodingCoreTests/FakeLink.swift`, `Core/Tests/BMWCodingCoreTests/DiagTests.swift`

**Interfaces:**
- Consumes: `CommandLink`, `ELM.parse`, `ISOTP`, `Log` from Tasks 1–3.
- Produces:
  - `public enum UDSResult: Equatable, Sendable { case positive([UInt8]); case negative(UInt8); case noResponse }`
  - `public final class Diag { public init(link: CommandLink, log: Log); public var readTimeout: Duration (default .milliseconds(1500)); public func setUp() async throws -> AdapterInfo; public func select(module: UInt8) async throws; public func request(_ module: UInt8, _ payload: [UInt8]) async throws -> UDSResult; public func readDID(_ module: UInt8, _ did: UInt16) async throws -> UDSResult; public func testerPresent(_ module: UInt8) async throws -> Bool; public func enterExtendedSession(_ module: UInt8) async throws -> Bool }`
  - `public struct AdapterInfo: Equatable, Sendable { public let model: String; public let firmware: String; public let elmVersion: String }`
  - `public extension ELM { static let initSequence: [String] }` = `["ATE0", "ATL0", "ATS1", "ATH1", "ATAT0", "ATST 32", "ATSP6", "ATCAF0", "ATCFC1", "ATSH 6F1", "ATFCSH 6F1", "ATFCSD 00 30 00 00", "ATFCSM 1"]`, sent after `ATZ` (3 s timeout, response discarded).
  - `setUp()` sends `ATZ`, then `initSequence` (each must answer `OK`, otherwise throw `LinkError.adapterError("<cmd>: <line>")`), then `ATI`, `STI`, `STDI`; `AdapterInfo(model: STDI line, firmware: STI line, elmVersion: ATI line)`.
  - `select(module:)` sends `ATCRA 6XX` and `ATFCSD XX 30 00 00` (XX = module address, upper-case hex, two digits; receive id is `0x600 + address` formatted as three hex digits) only when the module differs from the last selected one.
  - `request` sends `ISOTP.hexLine(ISOTP.singleFrame(to:payload:))`, collects `.frame` lines whose id is `0x600 + module`, reassembles; on `.needFlowControl` it sends `ISOTP.hexLine(ISOTP.flowControlFrame(to:))` and appends the frames from that response; `.complete(p)` with `p[0] == 0x7F` is `.negative(p[2])`, except code `0x78` (response pending) which waits 500 ms and retries the request once; any `.error` line throws `LinkError.adapterError(text)`; `.noData`, `.empty` or `.incomplete` give `.noResponse`, and so does anything but `.complete` after the flow-control round trip (both cases log a note with what was received).
  - `readDID` sends `[0x22, hi, lo]`; a positive whose first three bytes are `[0x62, hi, lo]` becomes `.positive(data after those three)`; a positive with any other prefix is `.noResponse` with a note.
  - `testerPresent` sends `[0x3E, 0x00]`, true on `.positive([0x7E, 0x00])`. `enterExtendedSession` sends `[0x10, 0x03]`, true on a positive starting `[0x50, 0x03]`.
  - Test support: `final class FakeLink: CommandLink { init(respond: @escaping (String) -> [String]); var sent: [String] }` where unknown commands answer `["OK"]`.

### Task 12: BLELink (CoreBluetooth)

**Files:**

  - `connect()`: if `UserDefaults.standard.string(forKey: "adapterIdentifier")` names a peripheral that `retrievePeripherals(withIdentifiers:)` returns, connect to it; otherwise scan for service `FFF0` and connect to the first result, saving its identifier.
